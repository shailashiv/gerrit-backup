[SW-140835] fwupd: delay implicit reset-state call

This patch aligns erom and preboot based on the patch below:
https://gerrit.habana-labs.com/#/c/255080/

Any kind of FIT error during fwupd procedure will stall for few minutes
using IB.

The original scenario was observed on a secured machine and a corrupted
FIT image. The FW rejected the update request as it was aware of the FIT
error.
The acknowledge appears immediately in the console. But the FWL doesn't
receive any indication about it, as it should have,
by receiving the SRAM_RUN error status FIT.

It appears that the fit error happens always when the preboot is in
"fast" mode. In order to send a status with a message back the preboot
should be in "slow" mode. A flag is set and the command module switch
the mode to slow, planing on sending the error status to the FWL. The
problem is, that because of the error path, an internal "reset state"
is invoked cleaning the flag.

This patch moved the call to reset-state to a later time, after the
error status is read by the host and send a RST_STATE request.
