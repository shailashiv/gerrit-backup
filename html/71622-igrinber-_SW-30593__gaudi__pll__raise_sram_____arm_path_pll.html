Commit Message

[SW-30593] gaudi: pll: raise sram <=> arm path plls

It was discovered that running most of the PLLs on the ARM <=> SRAM path
at their source frequency (50MHz) with no cache and MMU results in lot's
of instruction fetches from SRAM and slows down the CPU significantly,
so it even loses the data bytes on the I2C slave bus running @400KHz.
When the I2C slave bus runs @100KHz the CPU is able to get all the data
in time.
Raise the all the PLLs on the ARM <=> SRAM path to their nominal values.
We can decide later to lower them to the frequencies that will suffice,
but it will require more testing time.
