[SW-34719] gaudi: HBM init fail in err_sts opcode

HBM init failure reason in opcode 11
offset 136 (as per nvme mi 1.2 specification)
needs to be updated from info descriptor
table stored in flash during an hbm
initialization error.

This patch contains the changes to update
the hbm init failure reason in preboot.

Inline Comments

gaudi/rma_info.c

  • Noam Camus (Line 43): why not part of above rma structure?
  • Karthikeyan K (Line 43): The above structure "rma_failure" contains only active failure category wise (sram_ecc , hbm_ecc, hbm_init) . The reason for hbm_init failure is a seperature structure "rma_hbm_init_err". Where the first structure specifies if there is an hbm_init failure while the second one specifies what is the reason . The structure definitions are inherited from the source(uboot) which reports this error.

preboot/rma_info.c

  • Sailaja Bandarupalli (Line 188): why special handling for rma_hbm_init_err? why its not following boot descriptor kind of structure like sram ecc or hbm par?
  • Karthikeyan K (Line 188): preboot implementation is aligned with uboot(reporter of the error) . HBM init failure does not have multiple entries like sram_ecc and hbm_ecc does . HBM init is a single byte information that does not need an indexed storage for multiple table entries like it is needed for other errors .
