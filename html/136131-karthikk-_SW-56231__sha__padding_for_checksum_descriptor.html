[SW-56231] sha: padding for checksum descriptor

As the checksum size in image descriptor is adjusted to the
maximum number of bytes of the supported hash alogrithms
(sha384: 48 bytes), add support for padding to map the
indexing between primary and secondary image checksum.

For eg: for platforms which support sha256 as the hashing
algorithm img-ptr consists of checksum of the preboot image
to be loaded, i.e. a sha256(32 byte) hash for each primary
and secondary image consecutively. But now as the boot info
descriptor checksum is of 48 byte, the info descriptor api
look for the checksum at a delta of 48 bytes, hence causing
an indexing mismatch. By adding padding we fix this issue.
These extra padding bytes would not impact the checksum
calculation in the fit validation logic as the hash size is
the criteria to verify the limits of the hash bytes.

Hence this logic can be scaled in case there is a need to
support other hash algorithms with a bigger digest length.
