[SW-105874] gaudi2: remove usage of arc1 dccm for arc0

Currently, ARC0 performs pcie initialization sequence where ARC0
uses global variables from ARC1 DCCM using DMI address which are
initialized by ppboot running on ARC1. This requires the DCCM
address to be defined as DMI address so that ARC0 make use of ARC1 DCCM.

This also causes ARC1 to use its own DCCM using DMI address which leads
ARC stall issue in signature verification ROM function when DCCM is
accessed from internal and DMI address (details provided in SW-105874).

In order to overcome above mentioned issue, this patch add changes to
make ARC0 to use its own DCCM address and initialize required data
structures for pcie link routine. This change also make sure both
ARCs use its own DCCM via internal address so no access to DCCM
is performed via DMI.
