[SW-43025] fwupd: fixup i2c timeout on run

Since we moved to use internal API instead of registers for the I2C
indirect FW_UPD processes, we also need to cope with the need to sync
before executing the loaded image.
This is design bug in the FW_UPD protocol - when SRAM_RUN is replied
with status OK, Preboot is not syncing with the host/BMC that it got the
status and thus procedes to executing the image.
While in PCI this is not a problem as it is read independently by the
host, the I2C sufferes as it need an I2C indirect module for handing
the status over. Without a special sync code, the I2C module does not
get to run and serve the status OK.
This means that the status is not served anymore and in turn results in
timeout on the BMC hl-fw-loader.
To fix the timeout - add special sync code which is invoked on RUN_OK
status and delays the NO_RETURN execution by 200ms for the BMC to read
the status value.
After the timer expiration, the NO_RETURN command is executed and we
load the provided FIT which should take over the communication.
200ms was chosen as a relatively large and safe value.
Since this is not a time short critical execution path, we can use that
large value.
