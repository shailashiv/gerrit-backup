Commit Message

[SW-105911] common: split global data structure into two structures

Currently, ROM keeps the image data backup in first 3KB DCCM
persistent memory which is filled in cold reset from SPI and re-used
in non-cold reset based on validation pass flag. ROM doesn't make
use of boot info get api's to retrieve image information stored in
boot info in non-cold reset. This patch make following changes.

1. split global data structure into two parts global and manifest.
2. global data strcuture placed in 1st 512 bytes of DCCM which
will remain as persistent memory.
3. manifest data structure placed from 512 bytes to 3K of DCCM
which will remain as persistent/non-persistent based on boot info
skip flag. ie. If boot info skip flag in efuse is set, ROM will
need 3KB memory as persistent and other FW component should not
use it or override it.
