Commit Message

[SW-0] pll: rework the udelay routine

Current udelay code is buggy in following ways:
1) it makes various transactions during its invocation which hurts
   the delay accuracy.
2) it uses the CPU PLL DIV1 which is not the CPU clock but the time
   stamp clock for CPU timer. We do not use the timer here, so we
   should check the real CPU clock.
3) the assumption that the CPU PLL is the first in the PLLs array is
   not necessary.

So simplify the handling and make the necessary preparations before
the udelay code is invoked. In the udelay code, only do the really
necessary calculations and the delay loop itself.
