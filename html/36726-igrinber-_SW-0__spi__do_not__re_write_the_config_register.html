[SW-0] spi: do not (re)write the config register

During the Status Register write operation, we can also write the
Configuration Register, but we do not have to, as SR write operation can
end also after 8 bits of the SR content.
Remove redundant CR read and further CR write of the same content.

> This optimization may be valid but does backed by spec only our
 > field experience
 > What we save here few cycles?

Spec says:
"The sequence of issuing WRSR instruction is: CS# goes low→ sending WRSR instruction code→ Status Register data on SI→CS# goes high.

The CS# must go high exactly at the 8 bits or 16 bits data boundary; otherwise, the instruction will be rejected and not executed."

So I just follow it and raise CS# after 8 bits.
Moreover, U-Boot code does the same, it does not write the CR each time it writes SR...
