[SW-95918] gaudi2: security: set spi_dma security level to privilege

Recently SPI DMA was used at preboot stage for image validation from
flash (RAS requirement). This caused PSOC_AXI_ERR_RESP when security is
enabled as SRAM is closed by privilege RR by that stage and SPI DMA is
trying to copy to SRAM for validation. This is due to the security level
of spi_dma being a non-privilege level by default.

SPI DMA is used only by FW and copies data from SPI to various locations
including those accessible only by privilege entities. Also, all the
SPI DMA registers are privilege registers. So, it makes sense to assign
the SPI_DMA security level to privilege.

Hence, this patch sets the spi dma security level to privilege.
