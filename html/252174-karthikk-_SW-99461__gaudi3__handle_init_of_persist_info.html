Commit Message

[SW-99461] gaudi3: handle init of persist info

In order to handle the init of dccm in a cleaner manner, keeping the
persist info section at the beginning, the dccm init is split into
two operations:

1) Handle the non persist section's dccm init in startup every reset cycle.
2) Handle the persist section's dccm init only in cold reset using the
memcpy engine.

We need to take care of initializing the non-zero static info in persist
info only after the dccm init of persist info in order to avoid the
possibility of using a non-initialized dccm. This patch takes care of
this sequence.

+#define HL_ARC1_DCCM_PERSIST_SECTION_SIZE			(3 * 1024) /* 3KB */
+/*
+ * Note: base_readl() and base_writel() are used in arcboot_rom_persistent_dccm_init() instead of regmap_readl()
+ * and regmap_writel(). This is because regmap_* apis use the die id from global structure to calculate the die
+ * specific addressing and the same is required for accessing die1's register space.
+ * As the global structure itself should be used only after dccm persistent section init , we perform register
+ * accesses required by dccm persist init by manually computing the required addresses and using base_* apis.
+ */
+static void arcboot_rom_persistent_dccm_init(void)
+{
+	uint8_t die_id = regmap_readl(mmD0_PARC_LOCAL_CFG_DIE_ID);
+	uint32_t die_cold_rst_flop_2 = HL_CFG_BASE + mmCOLD_RST_FLOPS_2 + die_id * HL_CFG_SPACE_DIE1_OFFSET;
+	struct gaudi3_cold_rst_data cold_rst_data;
+
+	cold_rst_data.data = base_readl(die_cold_rst_flop_2);
+	if (cold_rst_data.arc1_persist_dccm_init_done)
+		return;
+
+	memset((void *)HL_DCCM_BASE, 0, HL_ARC1_DCCM_PERSIST_SECTION_SIZE);
+
+	/* Non zero initializers only required for master(die 0) */
+	if (!die_id)
+		arcboot_rom_persist_data_non_zero_init();
+
+	cold_rst_data.arc1_persist_dccm_init_done = 1;
+	base_writel(cold_rst_data.data, die_cold_rst_flop_2);
+}
