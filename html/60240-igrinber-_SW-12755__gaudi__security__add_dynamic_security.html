Commit Message

[SW-12755] gaudi: security: add dynamic security

The dynamic security is the concept when the FW dynamically open and
close memory windows for writing and reading by the non-privileged
entities.
Here the dynamic security is implemented according to host requests and
the predefined number of windows.

In addition the SRAM security involves the a W/A to H/W limitation.
The main limitation is the sharing of the same SRAM access router by
PCIe initiator and the TPC3 initiator. So to prevent TPC3 from accessing
the SRAM during the FW sensitive boot time, the "secured" Range
Registers are used (because TPC3 is user level of privilege) and the
privileged RRs of the same router are dynamically opened. This is
becaues the HBW routers uses the base + mask concept for protecting
memory regions and thus have a limitation of protecting sizes of maximum
the base aligned size. Yet to prevent the PCIe initiator to access
sensible memory regions, the "in PCIe_IF" RRs are used that are
implemented using the min/max concept - providing the needed flexibility
to handle various scenarios for access windows requirements.

To spare the dependencies between FW boot components, we cleanup before
loading the next component. The cleanup undoes the W/A and closes the
SRAM using the regular HBW router RRs.

+void preboot_security_dynamic_init(void)
+{

+	 * TPC_3 is sharing SIF_7 RTR with PCIe, so we close its access to SRAM

+		if (cfg->rr >= 0 && cfg->min && cfg->max)
+			preboot_secure_pcie_rr(cfg->rr, cfg->min, cfg->max);
+	}
