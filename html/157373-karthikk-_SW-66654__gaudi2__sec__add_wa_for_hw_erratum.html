[SW-66654] gaudi2: sec: add wa for hw erratum

Erratum:GAUDI2_0110
Problem:
PCIe master interface maintain credits towards HBM and PCIe.
However, due to hardware bug, there is a credit leakage.
Thus, if the region is blocked the first two transactions will
consume all the credits and all the transactions from the
3rd transaction onwards will blocked.

Implication:
The device does not provide downstream completion which will
cause the host to crash.

Workaround:
1) HBM- PCIE_MSTR_RR_MSTR_IF can be block only VA which is meaningless.
Instead use the HMMU RR which are working on PA.

2) PCIe (PCIe FW SRAM)- the memory should be removed from the BAR via
the iATU.

Changes in this patch for the above workarounds:
For 1) HBM non-HMMU RR programming in preboot is removed.
For 2) RR region for PCIe FW SRAM is removed in preboot as the region
is to be removed from the BAR via iATU.

Currently the issue was observed in PCIe FW SRAM and HBM as there two
memories have the credit buffer mechanism, hence impacted by the
credit leakage erratum. Other memories like SRAM, SP SRAM, DCCM/ICCM
etc did not showcase this issue.

In order to reproduce the issue, a pcie violation is to be triggered
on any of these memories, and a crash will be observed always on the
3rd violation(as the credit limit is 2).

In case any other memories showcase a similar issue in future, the iatu
region can be adapted accordingly as per requirement.
