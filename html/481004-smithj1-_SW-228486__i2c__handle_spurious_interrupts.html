Commit Message

[SW-228486] i2c: handle spurious interrupts

If the i2c_dw ISR is running while another interrupt is generated,
a second invocation of the ISR will be queued.  The second ISR will
read the device registers (specifically INTR_STAT) to decide what
if anything it needs to do.  It is not uncommon for this second
ISR to be a no-op and take no action.

On rare occassions, the INTR_STAT register indicates a TX_EMPTY
interrupt has been triggered. This is despite that the RAW_INTR_STAT
register does NOT have this bit set.  The ISR incorrectly tries to
complete the transfer by releasing the semaphore.  This breaks the
handshake between i2c_dw_transfer() and i2c_dw_isr(), preventing
any more transfers from being transmitted.

As a workaround, this patch tweaks tracking of the 'SEND' bit in
the driver state. When a transfer is completed successfully, the
SEND bit is cleared, along with the RECV bit.  The TX_FIFO logic
can then use this state to decide whether to ignore the TX EMPTY
interrupt.

Note that i2c_dw_isr() is used for both transmits and receives,
and that in order to receive data the driver needs to write to
the TX FIFO to 'ask' for the data.  This dual-use complicates
the i2c_dw_isr() logic; as such this patch uses a targetted
approach and mainly focuses on the TX_EMPTY case; it does not
attempt to deal with every possible case of getting bad data
from INTR_STAT or other registers.
