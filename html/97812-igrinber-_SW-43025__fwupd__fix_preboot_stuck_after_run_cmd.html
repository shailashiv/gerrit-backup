[SW-43025] fwupd: fix preboot stuck after run cmd

After RUN_SRAM command we used to have a call to reset state to indicate
that the state machine returned to the start.
Addition of the response FIT removed the reset state call so the memory
holding the response FIT will be left open and host can read the
response. This in turn also effectively removed the state machine reset
and thus Preboot has gone wild with the state machine not updated
correctly.
To fix this, we split the reset state routine to "secured" and
"unsescured" versions and call the unsecured version on on error thus
enabling the response FIT sending to host.
Additionally, to fix the state machine problem, we reset only the
relevant variables of the state machine.
