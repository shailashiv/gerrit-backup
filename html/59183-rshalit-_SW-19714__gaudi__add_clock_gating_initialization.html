Commit Message

[SW-19714] gaudi: add clock gating initialization

Until now, clock gating was enabled in LKD only.
Clock gating reduce power in HBW, and uses qman to
"auto" enable gating whenever there is a job.
But all this comes with a cost:
CG should have been done in HBW only,
but because of HW bug, CG always disables LBW too.
This flow prevent register access, and might even
result in PCIe deadlock, and host reset.
Therefore, it is considered as a security risk.
This patch solve it, by doing the following:
1. If security is not enabled, than we enable clock
gating already in preboot, to save power for cases
where device stays in preboot.
2. If security is enabled we boot with CG disabled
(default), and we also disable access to CG
registers, in order to prevent the security hole.
On enabling clock gating, we also enable a clock gating
status bit in status register, so that host shall know
if clock gating is done in FW or not.

+void hl_clock_gating_init(void)
+{
+	u32 i, base = 0, reg, val;
+
+	for (i = PCI_DMA_1; i < GAUDI_DMA_MAX ; i++) {
+		base = i * DMA_QMAN_DIFF;
+		/* Skipping of HBM_DMA_4 is workaround required by HCL */
+		val = (i == HBM_DMA_4) ? 0 : QMAN_PWR_GATE_EN;
+		regmap_writel(val, mmDMA0_QM_CGM_CFG1 + base);
+		reg = (i >= HBM_DMA_1) ? QMAN_CMN_PWR_GATE_EN :
+			QMAN_UPR_PWR_GATE_EN;
+		val = (i == HBM_DMA_4) ? 0 : reg;
+		regmap_writel(val, mmDMA0_QM_CGM_CFG + base);
+	}
+
+	for (i = 0 ; i < GAUDI_QM_CGM_NUM ; i++) {
+		base = MME_QM_CFG_DIFF * 2 * i;
+		reg = base + mmMME0_QM_CGM_CFG1;
+		regmap_writel(QMAN_PWR_GATE_EN, reg);
+		reg = base + mmMME0_QM_CGM_CFG;
+		regmap_writel(QMAN_CMN_PWR_GATE_EN, reg);
+	}
+
+	base = 0;
+	for (i = 0; i < GAUDI_TPCS_NUM; i++) {
+		regmap_writel(QMAN_PWR_GATE_EN, mmTPC0_QM_CGM_CFG1 + base);
+		regmap_writel(QMAN_CMN_PWR_GATE_EN, mmTPC0_QM_CGM_CFG + base);
+		base += TPC_QMAN_OFFSET;
+	}
+
+	cpu_boot_dev_sts_clrset(CPU_BOOT_DEV_STS0_CLK_GATE_EN, true);
