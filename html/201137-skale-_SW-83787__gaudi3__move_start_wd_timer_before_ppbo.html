Commit Message

[SW-83787] gaudi3: move start wd timer before ppboot execution

Currently, start of CPLD WD timer is performed much early before DMA
and verification of primary/secondary of ppboot image. This means that
if there is problem with ppboot primary/secondary image, ROM will still
start the WD timer and enter recovery flow. And since the preboot image
was not loaded the GPIO will not be de-asserted which is done in preboot
and CPLD will assert GPIO[2] after WD timer expires. This will lead to
FW entering recovery again after prstn/FW reset.

Ideally CPLD should assert GPIO[2] if there is problem in
ppboot/preboot execution or preboot image DMA/verification fails. In order
to make sure ROM enters recovery only once in above mentioned scenario,
this patch add changes to start CPLD WD timer just before jumping to
ppboot code which indicates that ROM has successfully DMAed/verified
ppboot image.
