Commit Message

[SW-47213] pci: avoid accessing hw when it's not ready

In some hosts the PRSTn signal might be asserted for a long time.
While it's asserted some hw block are held in reset and must not
be accessed.
after deassertion of the PRSTn signal the HW is performing
initialization sequence during which it's not advisable to access
it as well. (quoting Haim Revivo here)

Hence the sequense of the pci monitoring by preboot should be:
while PRSTn is low, there is no point reading any status regs. in fact
it's dangerous and might cause cpu exception.
after deassertion of the PRSTn we wait for the first link establishment,
that's our indication all the clocks are stable and HW FSMs operational.
and then we start monitoring the rest of the events (flr, hot reset,
link state, etc..)

In order to avoid duplication and race conditions, CPU1 is responsible
for the first stage of PRSTn and link monitoring.
CPU0 will monitor the running state of CPU1 and deduct the
pci state from there.
Meaning, if CPU1 has finished running (wfe state) or wasn't running
at all (reset state), then pci is initialized. otherwise pci
initialization is still in progress.

+bool is_pcie_initialized(void)
+{
+	u32 rst_ctrl, wfe_stat;
+
+	rst_ctrl = regmap_readl(mmCPU_CA53_CFG_ARM_RST_CONTROL);
+	rst_ctrl &= CPU1_RST_CTRL; /* reset signals are active low */
+
+	wfe_stat = regmap_readl(mmCPU_CA53_CFG_ARM_PWR_STAT_0);
+	wfe_stat &= CPU1_WFE_STAT;
+
+	/*
+	 * if CPU1 finished running (wfe) of didn't run at all (reset state)
+	 * pcie should be in operational state.
+	 */
+	return (!rst_ctrl || wfe_stat);
