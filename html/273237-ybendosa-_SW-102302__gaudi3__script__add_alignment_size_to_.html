[SW-102302] gaudi3: script: add alignment size to img size

The size of the complete image(Payload + Key + Signature) needs to be calculated
and placed in the manifest even before hashing and signing over it as the size
data itself needs to be hashed. Due to this we are required to calculate the
complete image size to be dmaed by considering payload + key + signature + CRC size.

PL NOTE: We also need to consider the 16 byte alignment in case the resultant
size of (payload + key + signature) is not 16 byte aligned. This is because
of dma requirement to place the crc at the end of a 16 byte aligned image.
Hence the final formula = ALIGN_16(Payload + Key + Signature) + CRC

Currently '(Payload + Key + Signature)' + CRC is calculated.
The patch fixes the formula to 'ALIGN_16(Payload + Key + Signature) + CRC'

This patch will currently have no functional impact as the image + key
+ signature size is aligned . But the dma crc will fail in case the image is not
16 byte aligned.
