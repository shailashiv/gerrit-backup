Commit Message

[SW-26273] fit: error response infrastructure

Instead of returning an anemic error value as a result
of a FW protocol response error. A future compatible,
more flexible, and more informative, approach is needed.

As a result of a FWLP error response, a FIT is being
been made by the FW, ready to be fetch by the FWL.
The current FIT used as a response of an error, is identical
to the one used by the proto_status protocol command.

In order to support the legacy code with minor changes.
The code "rides" over the module_fwupd_send_status command.

And the legacy send status command was renamed with the "_fast"
postfix.

+		 * so if the error inform function is called before entring the
+		 * current function, module_fwupd_send_status, the second call will not
+		 * overrun its values.
+		 * it allows support legacy code by setting the sent error status as protocol

+			 * block.

+			 * with request for change into SLOW MODE and execute a command state to

+			 * command state, so the alternative for that, is using a flag to ask for
+			 * running the state. That condition is not enough; an error should be

+			 * Both of those condition should be checked in the module's check and run
+			 * functions.
