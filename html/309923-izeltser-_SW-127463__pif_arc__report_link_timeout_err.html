Commit Message

[SW-127463] pif_arc: report link timeout err

According to PciE spec, link must be established within a given time
frame after prst_n release:
1. 100mS after cold boot
2. 20mS after warm reboot

PIF ARC monitors this condition and flag an error if timeout
has occurred.

Arming of the pif TS counter is moved to the main pcie monitoring
function pif_arc_pcie_monitoring() so it will be clear that this
counter is being armed right after prst_n is deasserted.

+/*
+ * PIF is being reset only by PRST_n signal (warm reboot) or power cycle (cold boot).
+ * Due to a known bug in the psoc rst_src register, this register should never be cleared, only
+ * power cycle is clearing it. Hence, we are looking for 2 scenarios:
+ * 1. PRST_n indication is on == last reset source was warm reboot
+ * 2. PRST_n indication is off == last reset source necessarily was cold boot.
+ */
+static enum pif_reset_source pif_get_reset_source(void)
+{
+	u32 regval = regmap_readl(D0_PSOC_GLOBAL_CONF_REG(mmGLOBAL_CONF_RST_SRC));

+	if (regval & GLOBAL_CONF_RST_SRC_PRSTN_RST_IND_M)
+		return PIF_WARM_REBOOT;
+
+	return PIF_COLD_BOOT;
