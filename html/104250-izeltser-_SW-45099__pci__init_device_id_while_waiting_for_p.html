Commit Message

[SW-45099] pci: init device id while waiting for prstn

This patch solves 2 issues:
1. for some devices the efuse is read in order to assemble the
   device id. efuse reading is a fairly long operation and shouldn't
   be performed in time critical points in the code. for those
   devices the pci id is initialized while we are waiting for prstn
   de-assertion, and used later on when required.
2. Tests show that accessing pci_dbi registers during link
   establishment might cause the cpu to hang. because of that, it's
   risky to fetch the pci dev id from the pci_dbi block. instead,
   the pci dev id is initialized during preboot boot sequence and
   used later on when required.
