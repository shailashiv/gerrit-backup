Commit Message

[SW-117471] erom: tpm init: fix dev wait condition

Before starting TPM initialization, we call tpm_tis_wait_init() to wait
for SPI communication with TPM to start.

We assume this happens once we are able to read locality reg and see
bit 7 (TPM_ACCESS_VALID) is on.

However, it seems that while TPM device is coming up and not yet ready
to communicate, we effectively read 0xFFs from the locality reg - this
means our bit 7 check passes whereas the TPM is not really ready for
communication and might start tpm initialization too early.

This change waits for a value other than 0xFF to be read before going
on with TPM initialization.
