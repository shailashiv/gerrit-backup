Commit Message

[SW-66407] gaudi3: add barrier before polling on mem cpy status

After configuring and enabling the mem_cpy engine FW is polling on the
completion status.
since the first read of the polling loop is very close to the 'enable'
bit write, and we don't have read-write coherency, the first read may
return before the enable bit was actually written, and outdated status
would be used.
A write barrier is added before the polling cycle in order to make sure
the engine is enabled before polling on the status.
