Commit Message

[SW-43160] gaudi: offload pci link monitor to cpu1

PCI link may appear at any stage, not just on boot. It needs to be
monitored and handled swiftly or else the link remains broken.
Preboot contains a good number of routines which may cause a delay to
pci link monitor polling module since they shared the same core.

This patch utilizes the secondary ARM core for PCI link monitoring. This
way is can be done in parallel with the rest of preboot logic.

In addition, PCI link handling (HW WA) was removed from CPU0 PCI module.

+void preboot_pcie_wait_for_link(void)
+{
+	u32 rst_addr_lsb, rst_addr_msb, rst_ctrl;
+
+	/*
+	 * Call preboot_security_is_enabled() before offloading PCI work to
+	 * CPU1 is needed because we don't want CPU1 to init fuse or access OTP
+	 * while CPU0 is running and may attempt access the same resource.
+	 * Performing this call fills the fuse/OTP cache so a secondary call
+	 * will only read from cache.
+	 */
+	(void)preboot_security_is_enabled();
+
+	rst_addr_lsb = (u32)(uintptr_t)secondary_entry;
+	rst_addr_msb = (u32)(uintptr_t)(((uintptr_t)secondary_entry) >> 32);
+	regmap_writel(rst_addr_lsb, mmCPU_CA53_CFG_RST_ADDR_LSB_1);
+	regmap_writel(rst_addr_msb, mmCPU_CA53_CFG_RST_ADDR_MSB_1);
+
+	rst_ctrl = regmap_readl(mmCPU_CA53_CFG_ARM_RST_CONTROL);
+	rst_ctrl |= CPU1_RST_CTRL; /* Take CPU1 out of reset */
+	regmap_writel(rst_ctrl, mmCPU_CA53_CFG_ARM_RST_CONTROL);
