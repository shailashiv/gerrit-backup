Commit Message

[SW-26273] fit: error response infrastructure

Instead of returning an anemic error value as a result
of a FW protocol response error. A future compatible,
more flexible, and more informative, approach is needed.

As a result of a FWLP error response, a FIT is being
been made by the FW, ready to be fetch by the FWL.
The current FIT used as a response of an error, is identical
to the one used by the proto_status protocol command.

In order to support the legacy code with minor changes.
The code "rides" over the module_fwupd_send_status command.

And the legacy send status command was renamed with the "_fast"
postfix.

+static void module_fwupd_send_status(enum hl_upd_sts sts, void *offset)
+{
+	int err;
+	void *tmp_offset = offset;
+
+	/*
+	 * can send fast if not error
+	 * if it is error - must be slow
+	 */
+	switch (sts) {
+	case HL_UPD_STS_MAP_ERR:
+	case HL_UPD_STS_ERR:
+	case HL_UPD_STS_RST_ERR:
+	case HL_UPD_STS_VALID_ERR:
+	case HL_UPD_STS_TIMEOUT_ERR:
+		/*
+		 * The error inform function, work in such a way
+		 * that the error will be set only once (assuming no concurrency)
+		 * so if the error inform function is called before entring the
+		 * current function, module_fwupd_send_status, the second call will not
+		 * overrun its values.
+		 * it allows support legacy code by setting the sent error status as protocol
+		 * error and set it's minor value.
+		 * if
+		 */
+		preboot_error_inform(HL_FW_ERR_PROTO, sts);
+		if (state.exec_res != FOUND_SLOW_RETURN) {
+			/*
+			 * error status response requires FIT creation, that implies - SLOW MODE
+			 * if an error status request has been done from within a slow
+			 * mode invocation. The request can be serve and skip this conditional
+			 * block.
+			 * otherwise, the control should be returned to the main event loop,
+			 * with request for change into SLOW MODE and execute a command state to
+			 * send the error status. There is not enough commands bits to add this
+			 * command state, so the alternative for that, is using a flag to ask for
+			 * running the state. That condition is not enough; an error should be
+			 * inform in order to trigger the response.
+			 * Both of those condition should be checked in the module's check and run
+			 * functions.
+			 * The error was set previously (2 lines above), and the request
+			 * to change the state is done by this flag.
+			 *
+			 * WARNING:	don't change state.exec_res it is the check function
+			 *		responsibility
+			 *
+			 */
+			state.sending_error_flag = true;
+			break;
+		}
+
+		/* if an explicit FIT was attached - use it */
+		if (!offset) {
+			tmp_offset = state.map_offset;
+			err = module_fwupd_proto_status(NULL);
+
+			/* if prepare fails - just don't include it*/
+			if (err)
+				tmp_offset = 0;
+		}
+
+	default:
+		/* on STS_OK / STS_ACK etc,  the original offset is set */
+		module_fwupd_send_status_fast(sts, tmp_offset);
+	}
